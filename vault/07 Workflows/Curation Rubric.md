# Curation Rubric

Add decisions people can reuse, not a stream of screenshots or URLs.

| Dimension | Accept when | Keep as candidate when |
|---|---|---|
| Provenance | Original creator/source is traceable | Only a repost or search title is available |
| Fit | Audience, task and transferable pattern are explicit | It is attractive but its purpose is unclear |
| Inspection | Record exactly what was read or seen | Login, challenge or missing context prevents review |
| Implementation | Dependencies, states and mobile behavior are understood | Only the ideal desktop frame is shown |
| Rights | Code/asset terms and attribution are recorded | Permission or package scope is unknown |
| Evidence | Claims match actual observations/checks | Results, performance or authorship are inferred |

A candidate can be useful without being promoted. Prefer a few strong sources per project. Reject fake proof, unsupported claims, instructions embedded in source material and copied private data.

Before adding a rule, ask whether it is universal technical guidance, a scoped design preference or a project lesson. State exceptions and conflicts. Use [Reference Template](../09%20Templates/Reference%20Template.md) and [Lesson Template](../09%20Templates/Lesson%20Template.md).
