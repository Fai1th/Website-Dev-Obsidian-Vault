# Retrieval and Maintenance

The token-saving mechanism is selective retrieval. Obsidian stores notes; an agent still has to read them. This library makes no measured token reduction claim.

- Keep entry/core small. Use maps as routing lists, not instructions to open every link.
- Start with filename search, then load the selected genre/component/control.
- Keep code, long source snapshots and research archives outside the initial path.
- In project manifests, store note paths, package versions, decisions and verification evidence. Do not duplicate the complete ruleset.
- New research enters as candidate or observed. Promote it only after enough inspection; mark tested only with actual evidence and scope.
- Recheck security guidance and package APIs when implementing. Review inspiration for link rot periodically when using it.
- Append a change reason when altering a rule. Keep project exceptions visible.
- Do not store credentials or private client data. Keep the vault local unless sharing is explicitly authorized.

Useful searches: Obsidian `path:"02 Genres"`; `path:"04 React/Components" dialog`; filesystem `rg --files` then targeted `rg` within selected folders. Avoid recursive searches inside the snapshot unless investigating source.
