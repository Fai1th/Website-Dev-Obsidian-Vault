# Build Workflow

Repeat decisions and verification, while adapting visual expression to the content.

1. **Brief:** audience, primary task, content, assets, stack, constraints and success criteria. Use [Project Brief Template](../09%20Templates/Project%20Brief%20Template.md).
2. **Audit:** existing system, working behavior, project rules and defects. Preserve what the brief does not authorize changing.
3. **Choose:** one genre, one foundation, page structure and a small reference set. Record exact note paths and exceptions.
4. **Specify:** tokens, section purpose, component contracts, mobile order, state cycles and relevant security boundaries.
5. **Adopt:** review selected React sources and license; pin versions; inspect imports; style to the brand. See [Source Adoption](../04%20React/Source%20Adoption.md).
6. **Build:** use real content early, isolate behavior, implement all required states, maintain semantic structure.
7. **Verify:** repository checks plus representative user journeys and [Professional Release Checklist](../06%20Quality/Professional%20Release%20Checklist.md). Save evidence and unresolved limits.
8. **Remember:** save only validated reusable lessons and source/version changes. A one-off workaround remains project-scoped.

For a new chat, start with the entry/core, selected notes and the project manifest. Do not paste the whole library. For an existing project, load its manifest before repeating research.
