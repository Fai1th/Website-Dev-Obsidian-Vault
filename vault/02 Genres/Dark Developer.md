# Dark Developer

Best for: Developer tools, documentation, technical products.

Intent: Useful technical content with restrained atmosphere.

## Page structure

Technical promise > working example > capabilities > documentation/integration > evidence > action.

## Rules

Use real code, documented APIs and accurate product behavior. Keep code horizontally scoped, copy actions labeled, errors readable and syntax colours tested. Distinguish an example from a live environment.

## Professional exception

A restrained dark palette, monospace metadata and real version information fit docs and tools. [Dark Accent Profile](../01%20Foundations/Dark%20Accent%20Profile.md) can justify lavender.

## Avoid

Avoid fake terminal logs, decorative uptime dots, fake sync/version stamps and unreadable grey-on-black body copy.

## Mobile and validation

Allow code blocks to scroll independently without making the page overflow. Keep prose readable and copy controls accessible.
